# Hybrid・Path Tracing・透過屈折の今後のテーマ

作成日: 2026-10-31
状態: 今後の検討・作業メモ。ここに挙げる案は、実装済みと記載したものを除き未実装。

## 背景と方針

Cornell Box、Sponza、DamagedHelmetをHybridとNative PTで比較した。両方式の画像を
一致させること自体は目標にしない。それぞれを実用的にし、Native PTはHybridの
近似や透過・屈折を評価する際の比較基準として精度を高める。

Cornellの最初の比較では共通の点光源を用いたが、現行Hybridの影は選択された
平行光源に限定されるため、Hybrid側に点光源の影がなかった。その後、共通の
平行光源で撮り直し、両方式で球の影を確認した。Cornellは比較用に構成した
シーンであり、標準の内蔵シーンと同一であることは主張しない。

比較画像と設定はローカル生成物のためGit管理対象ではない。

- Cornell、共通平行光源: `bin/PathTracingValidation/cornell-directional-comparison-20261031/`
- Cornell点光源・Sponza・Helmet: `bin/PathTracingValidation/pt-hybrid-three-scenes-20261031/`
- 比較画像のPTは512 spp、最大8バウンス、RR/NRD OFF。各ペアのカメラ、
  シーン、照明、露出は共通。画質の参考であり、性能比較や正しさの合格判定ではない。
- 比較用スクリプト: `Tests/PathTracing/capture_pt_hybrid_comparison.py`。
  点光源版ではHybridに点光源の影がないため、Cornellは平行光源を既定とする。

## 1. HybridのDiffuse・間接光

### 現状と課題

- 現行Hybridは直接光とDiffuse IBLなどで照明する。IBLをOFFにすると、直接光が
  届かないDiffuse面は多重反射による間接光がないため暗くなる。
- 一方、Sponzaの環境光のみの比較ではHybridが明るかった。Diffuse IBLの参照は
  建物の壁や屋根による空への遮蔽を十分に表現しないため、室内の過剰照明が
  含まれる可能性が高い。ただし、この画像だけで原因や正しさを確定しない。
- 現行のHybrid直接光シャドウは、選択された1つの平行光源が対象。点光源の影の
  対応は別の作業とし、光源数や照明全体の設計と合わせて扱う。

### 今後の候補

1. **Ambient Fill**: IBLと独立にON/OFFできる、定数色または上下2色の簡易補完。
   強度、色、AO適用量を調整可能にする。デフォルトOFF。AlbedoとMetallicを
   考慮するが、光の輸送や色移りを再現する物理GIとは呼ばない。
2. **IBLの遮蔽改善**: 室内での過剰照明を調べ、AOや可視性情報をどう使うか検討。
   Ambient Fillで暗部を持ち上げる問題とは分ける。
3. **Probe / DDGI**: 空間に配置したProbeから間接Diffuseと色移りを近似する。
   更新方式、遮蔽・壁越しの光漏れ、密度、コストを評価する。環境光をProbeに
   含める場合は既存Diffuse IBLとの二重加算を避ける。

Hybridの変更はこのメモだけでは開始しない。実装時は別作業として切り出し、
鏡面IBLや直接光の影への影響、設定の後方互換性を確認する。

## 2. Native PTの品質・正確性

### 現状

- Sponzaは環境光のみ・同じ露出の比較で、PTがHybridよりかなり暗かった。
  PTは壁や屋根による遮蔽を追跡する一方、HybridのDiffuse IBLは同じ遮蔽を
  再現しない。差の一因にはなり得るが、PTの暗さが妥当か不具合かは未判定。
- DamagedHelmetでは、glTFに接線がなくPTで法線マップが使われていなかった。
  PT専用のMikkTSpace接線生成で修正済み。金属度・粗さの入力検証では、対象の
  ケースにチャンネル・係数の不具合は見つからなかった。
- GGXのサンプリングと分布評価を数値的に安定化した。現行のalpha下限0.001は
  維持中で、低粗さの差が失われる制約は未解消。Helmetの見え方の唯一の原因とも
  まだ断定できない。

### 今後の作業

1. **Sponzaの照明切り分け**: 同じカメラ、環境、露出、共通の直接光で比較し、
   環境光のみの場合との差を確認。環境の方向・強度、材質入力、遮蔽、バウンス数と
   蓄積の収束を調べる。露出変更やAmbient追加で原因を隠さない。
2. **低粗さGGX**: 斜視角、混合BSDF、PDF/MIS、エネルギーの整合性を検証してから、
   下限や完全鏡面の扱いを検討する。数値安定性と回帰テストを維持する。
3. **画質と再構成**: Native PTを先に評価し、その後、同条件でRR/NRDを比較する。
   デノイズ結果だけでNative PTの誤りを覆い隠さない。

詳細: [Helmet反射品質の調査](pt-helmet-reflection-quality.md)。

## 3. 透過・屈折・glTF

### 実装済みの範囲

- Native PTの薄膜透過、透過率・透過色・粗さのテクスチャ、粗い薄膜透過、
  Alpha MASK、金属度との混合を段階的に実装・検証した。
- 限定条件下のVolumeとして、入射・出射境界での屈折と全反射、内部の実距離に
  応じた色付き吸収を実装した。Scene EditorのVolume設定と限定glTF入力にも対応。
- 限定glTF Volumeの対象は、単一の閉じた凸形状などに限られる。検証用の固定
  シーンで輪郭のmissed exitを0にしたが、すべての形状を保証するものではない。

### 未完成・今後の作業

- 粗い表面のVolume屈折、凹形状、複数プリミティブ／材質、入れ子・重複媒体、
  媒体内部にあるカメラ、Volumeテクスチャなどの対応範囲拡大。
- glTF拡張や複合材質を含む、より広い実データでの受理条件と描画品質の確認。
- **最終目標のステンドグラスを通る色付き照明**。色付きシャドウの近似と、
  屈折光路・コースティクスを扱う方式を区別して検討する。
- 対応範囲を広げたユーザー目視確認と、Volumeを含むRR/NRDなど再構成品質の
  個別検証。現在の限定Volumeの数値検証を、そのまま全組み合わせの承認としない。

詳細: [Volume透過計画と検証](path-tracing-volume-transmission.md)、
[粗い薄膜透過](path-tracing-rough-transmission.md)、
[透過テクスチャ](path-tracing-transmission-textures.md)、
[金属度との混合](path-tracing-metallic-transmission.md)。

## 推奨順序

1. SponzaのPT照明を切り分け、Native PTの比較基準を固める。
2. 低粗さGGXの残る数値・エネルギー検証を進める。
3. 透過・屈折の対象範囲を広げ、色付き透過光への道筋を詰める。
4. HybridのAmbient Fill、IBL遮蔽、Probeを別作業として設計・評価する。

Hybridと透過・屈折は別ワークで並行検討できる。ただし、同じレンダラやマテリアル
契約を変更する場合は担当範囲と統合順序を先に確認する。
